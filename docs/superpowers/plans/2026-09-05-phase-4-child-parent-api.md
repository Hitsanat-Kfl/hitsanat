# Phase 4 — Child & Parent API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Child API (Registration & CRUD) and Child-Parent Linking API.

**Architecture:** DDD modules following existing Phase 3 patterns. Drizzle repositories, use cases, controllers, routers. Reuse existing validation schemas and domain entities.

**Tech Stack:** Express, Drizzle ORM, PostgreSQL, TypeScript, Zod validation, Vitest

**Spec:** ClickUp tasks CORE-026 and CORE-027

## Global Constraints
- Node >=20, pnpm 9.15.9, TypeScript strict
- Biome for formatting/linting
- All dates stored as Gregorian/UTC
- UUIDs generated by PostgreSQL defaultRandom()
- All API responses follow { success, data?, error? } shape
- DDD module structure: domain/, application/, infrastructure/, presentation/
- Use getDb() from @repo/database (lazy singleton)
- Auth middleware from @repo/auth/middleware
